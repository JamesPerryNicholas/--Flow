# 灵境 Flow

类似 Coze 的本地智能体工作流画布。原生 HTML、CSS、JavaScript，服务端仅使用 Node.js 标准库，无需安装依赖。

## 启动

在本目录执行 `npm start`，访问 [本地工作台](http://127.0.0.1:4173)。需要 Windows 和 Node.js 18 或更新版本（开发验证环境为 Node.js 22）。服务仅监听本机地址。

## 已实现

- 无限画布：平移、缩放、适应内容、缩略图定位。
- 开始、结束、智能体、大模型、知识库、条件分支、HTTP 请求、循环批处理八种节点。
- 点击或拖入节点，拖拽移动，点击或拖拽端口连线，点击连线删除。
- 节点配置、复制与删除、撤销重做。
- 多工作流切换、新建、删除；浏览器本地自动保存；JSON 导入导出。
- 统一模型管理：新增、编辑、启停、删除、测试连接；所有工作流共享模型配置。
- 智能体和大模型节点独立选择模型，按连线执行真实模型请求；系统提示词和上游结果参与生成。
- 真实执行与本地模拟切换、运行取消、逐节点结果和最终输出；失败即中断并显示错误。
- 连线检查：禁止环形连线、重复出口、多输入以及错误的起终点方向；数组循环使用批处理节点。
- 变量引用：用户输入、系统提示词、模拟模板和最终输出可组合原始输入与祖先节点输出，提供变量选择器和运行前校验。
- 结构化变量：选择 JSON 对象字段和数组元素；支持文本/JSON 输出声明、运行时格式校验，以及 HTTP 正文保留原始 JSON 类型。
- 运行历史：按工作流保留最近 20 次，查看节点输入、输出、提示词、耗时和错误；支持复用输入，区分成功、失败、取消与刷新中断。
- HTTP 工具：调用外部接口，安全填充 URL 与 JSON 正文，提取响应字段传给模型；统一加密管理工具凭据，记录请求与响应状态。
- 循环批处理：遍历 JSON 数组，逐项执行可复用的工作流、顺序汇总结果；支持子流程编辑、逐项日志、停止和依赖流程一起导入导出。
- 统一知识库：导入或编辑文档、自动切片、本地全文排序；工作流选库检索，输出与运行历史保留来源。
- 发布与调用：固定主流程及子流程版本，独立应用页选择版本运行，提供本机运行 API；支持下架、恢复和应用运行历史。

## 当前边界

模型接口目前支持 OpenAI 兼容的非流式 Chat Completions 协议；外部工具需显式放置 HTTP 节点，不支持模型自主选择工具、内置联网搜索或对话记忆。智能体节点当前为带角色提示词的模型节点，还不具备自主工具循环。知识库采用本地 BM25 全文检索，尚无向量语义检索或 PDF、Word 解析。流程为单输入、单活动路径；条件节点支持是/否两条出口。支持顺序数组批处理，尚无 while 循环、并行汇聚、多人协作、云端存储或账号。发布入口与 API 仅当前电脑可访问。

工作流与运行历史保存在浏览器当前来源的 localStorage 中，不跨浏览器同步；清除浏览器数据会删除这些内容，请用导出备份工作流。模型、工具凭据和知识文档由本机服务端单独保存。

## 接入模型

1. 点击右上角“模型管理”，填写显示名称、模型 ID、接口基础地址和服务商 API Key。本机无鉴权的模型服务可以留空 Key。
2. 保存后点击“测试连接”。测试和真实运行会向所填地址发送请求，可能产生服务商费用。
3. 选择画布上的智能体或大模型节点，在“调用模型”中选择已启用的配置。
4. 打开“试运行”，使用“真实执行”模式执行。无需联网验证流程时，切换“本地模拟”：模型与 HTTP 节点使用模板，文档库节点仍检索本地资料。

接口可填 `https://你的服务地址/v1`，也可填完整的 `/chat/completions` 地址。本机允许 `http://localhost:端口/v1` 或 `http://127.0.0.1:端口/v1`。URL 不接受内嵌凭据、查询参数和片段。接口格式参考 [Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

模型配置使用 Windows 当前账户的 DPAPI 加密保存在 `.local/models.enc`，不写入浏览器 localStorage。此文件被 Git 忽略，不应作为可跨机器使用的备份；换 Windows 账户或机器需要重新配置。编辑时 Key 留空保留原密钥，更换接口域名或端口时须重新填写。工作流 JSON 仅携带模型引用，导入其他机器后需要重新选模型。停用或删除模型不会自动替换节点配置，真实运行会要求重新选择。

执行前检查所有可达分支的路径、变量引用、模型、工具与文档库配置。运行中修改工作流、切换节点或打开模型管理、工具凭据、知识库、运行历史会取消当前运行；取消不能撤销上游已发生的费用或数据写入。

## 接入知识文档

1. 点击顶部“知识库”，命名并保存文档库。所有工作流可共享同一个库。
2. 点击“导入文件”，选择 UTF-8 编码的 `.txt`、`.md`、`.markdown`、`.csv` 或 `.json` 文件；也可新建文本。导入后检查正文，再点击“保存文档”。CSV 与 JSON 按原始文本处理。
3. 保存后自动按约 600 字符切片，相邻片段重叠 80 字符。可在“检索测试”查看文档名、片段和相关分；相关分用于排序，不代表置信度。
4. 在画布添加“知识库”节点，选择文档库、设置检索输入和返回片段数（1–10），连接到模型节点。文本输出包含 `[1] 文档名 · 片段编号`；模型需通过提示词要求保留引用。
5. 选择 JSON 输出可获得 `knowledgeId`、`knowledgeName`、`query`、`hits`；例如下游用户输入填 `{{input#/hits/0/text}}` 读取第一条正文。无匹配时 `hits` 为空，此路径会报缺失字段；需按业务设计后续分支。

检索不调用外部模型，本地模拟也会查询已保存资料。当前采用 BM25 词项匹配与排序，不推断同义词；没有命中时返回明确的空结果。运行详情和历史保留来源名称、片段编号、相关分及正文快照；长历史字段可能截断。旧流程的内联文本检索继续兼容。

每个文档最多 100000 字符、导入文件最多 400000 字节；每库最多 100 篇、共最多 50 个库，总正文最多 5000000 字符。资料以明文保存在 `.local/knowledge.json`。工作流导出只携带文档库引用，不包含文档；迁移时需单独备份此文件，可停止服务后复制。删除文档库会使引用它的节点不可用，需重新选库。

## 接入 HTTP 工具

1. 从节点库添加“HTTP 请求”，连在开始节点和需要使用接口结果的节点之间。
2. 选择 GET、POST、PUT、PATCH 或 DELETE，填写完整 URL。远程接口使用 HTTPS；本机允许 HTTP。路径和查询参数可引用变量，变量会自动进行 URL 编码；协议、主机和端口须固定。
3. POST、PUT、PATCH 可填写 JSON 正文，在字符串值中插入变量，例如 `{"query":"{{input}}"}`。输入中的引号和换行会自动转义；字段名不支持变量。GET、DELETE 不发送正文。
4. 如需认证，在右上角“工具凭据”保存显示名称、目标来源、认证头和完整认证值，再在节点中选择。Bearer 认证值应包含 `Bearer ` 前缀。目标来源只填写协议、域名和端口，例如 `https://api.example.com`；凭据仅发送至该来源，更换来源或认证头需重新填写认证值。
5. “提取响应字段”留空返回完整文本；填写 `/data/items/0/title` 可提取 JSON 字段，规则遵循 [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901.html)。字段名中的 `/` 写为 `~1`，`~` 写为 `~0`。缺失字段或无效 JSON 会中断流程。
6. 真实执行后，可展开节点结果查看实际请求、HTTP 状态和内容类型。本地模拟只使用模拟响应模板，同样执行字段提取，不发送工具或模型请求。

凭据使用当前 Windows 账户的 DPAPI 加密保存在 `.local/tool-credentials.enc`，接口只返回名称和配置状态，认证值不回显，也不进入工作流导出或浏览器存储。接口回显的原始认证值会脱敏；不要把密钥直接写在 URL、正文或模板中，这些内容会保存在流程与运行历史中。

工具超时可设为 1–60 秒，响应上限为 1 MB、输出上限为 100000 字符。失败、超时或停止会中断后续节点；不会自动重试或跟随重定向。真实调用可能写入外部数据，停止不能撤销已发送请求。当前不支持文件上传、自定义普通请求头、流式响应及 OAuth 流程。

## 引用节点变量

在节点的“用户输入”“系统提示词”或模板下方，用“引用变量”选择需要的来源。只有当前节点的祖先输出可选，节点重命名不会改变已有引用。

- `{{input}}`：用户输入配置中表示直接上游输出；提示词和模拟模板中表示当前节点解析后的用户输入；结束模板中表示直接上游输出。
- `{{start.input}}`：本次试运行的原始文本，始终可在下游使用。
- `{{nodes.节点ID.output}}`：指定祖先节点的实际输出，由选择器自动插入；特殊 ID 自动编码。

例如润色节点的用户输入可以填写“主题：`{{start.input}}`\n初稿：`{{nodes.前一节点ID.output}}`”。条件节点的输出保留用于判断的文本，判断结论另行记录。变量只展开一次，上游返回的模板文字不会被再次执行。

### 引用 JSON 字段

1. 在节点配置中选择“输入类型”（开始节点）或“输出类型”为 JSON，实际内容必须是有效 JSON，否则中断并标记出错节点。模型需通过提示词约定返回格式，选项不会自动修改模型请求。旧工作流默认文本。
2. 点击输入框下方“选择 JSON 字段…”，选择上游来源，再点击字段或数组元素。选择器使用本机运行历史展示示例，也支持粘贴 JSON 示例；示例仅供参考，不加入流程或请求。没有示例时可手动填写路径。
3. 例如 `{{nodes.节点ID.output#/data/items/0/title}}` 读取祖先输出中的标题；`{{start.input#/topic}}` 读取原始输入；`{{input#/count}}` 读取当前输入的字段。`#` 后留空引用整个 JSON。路径遵循 JSON Pointer，数组下标从 0 开始，特殊字符规则同响应字段提取。
4. 在 HTTP JSON 正文中，字符串值完整包含一个结构化引用时保留原类型，例如 `{"count":"{{input#/count}}","tags":"{{input#/tags}}"}` 可传递数字和数组；混合文字的插值仍为字符串。未带 `#` 的旧引用保持文本行为。

结构化引用按来源实际内容解析，即使来源声明文本，只要内容是有效 JSON 也可读取字段。`0`、`false`、`null` 和空字符串均保留；缺失字段、无效 JSON 会中断后续节点。非法路径和不可用来源在任何外部调用前拒绝。类型声明、字段引用随工作流保存与导出，运行历史显示 JSON 输出标记。

### 配置 JSON 字段规则

选择 JSON 类型后，可在“JSON 字段规则（可选）”填写规则，或点击“填入对象规则示例”。例如下面的规则要求对象含有非空标题，并逐项检查标签：

```json
{
  "type": "object",
  "properties": {
    "title": { "type": "string", "minLength": 1 },
    "tags": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["title"],
  "additionalProperties": false
}
```

这是 [JSON Schema 2020-12 校验词汇](https://json-schema.org/draft/2020-12/json-schema-validation)的明确子集，支持布尔规则、`type`（含 `integer`、可空类型数组）、`properties`、`required`、`additionalProperties`、`items`、`enum`、`const`、`minItems/maxItems`、`minProperties/maxProperties`、`minLength/maxLength`、`minimum/maximum`、`exclusiveMinimum/exclusiveMaximum`，以及注解 `title/description`。未知关键字直接报错，包括尚不支持的 `$schema`、`$ref`、`format`、`pattern`、组合规则和旧版元组式 `items`。类型专用规则仅对对应类型生效，例如 `required` 本身不要求输入是对象，需搭配 `type: "object"`。

运行和发布前检查全部可达分支及子流程的规则；每个节点得到实际 JSON 后再次检查数据。错误显示所属节点与 JSON Pointer 字段路径，根值显示 `$`；失败即停止，后续节点不执行。HTTP 节点检查提取后的响应，批处理检查汇总数组，子流程可另设自己的输入与输出规则。规则不展开变量、不转换类型、不填默认值，也不会自动修改模型请求或修复输出。

规则草稿可保存、撤销、导入导出；语法错误会即时提示，运行与发布时拒绝。留空仅校验 JSON 格式；切回文本后停用字段规则并保留内容。发布版本固定保存当时规则。每份规则最多 50000 字符，完整规则 JSON 树（包括枚举值与注解）最多 1000 个值、深度 32；实例深度最多 64，校验访问最多 100000 步。历史示例仅供选字段参考，不代表当前版本的输出结构。

尚无表达式计算、自动格式修复或对象字段自动补全。

## 循环批处理

1. 添加“循环批处理”节点，将数组放入“数组输入”，例如 `{{input}}` 或 `{{nodes.上游节点ID.output#/items}}`。解析后的内容必须为 JSON 数组；空数组直接返回 `[]`。
2. 选择已有的“单项处理流程”，或点击“新建单项处理流程”。子流程收到 JSON 对象 `{"item":当前项,"index":从0开始的下标,"total":总数}`；用 `{{start.input#/item}}` 读取当前项，可在子流程继续组合模型、HTTP 和条件节点。
3. 点击“编辑单项流程”进入其画布，顶部按钮返回父流程。子流程是共享工作流，修改会影响所有引用它的父流程的后续运行。模型仍从统一模型管理中选择。
4. 设置数量上限与“单项结果类型”。文本结果汇总为字符串数组；JSON 结果要求子流程的最终输出为有效 JSON，汇总时保留数字、布尔、对象和 null 等类型。批处理节点的输出始终为 JSON 数组。
5. 试运行按输入顺序执行，运行详情与历史显示子流程名称、项序号、子节点输入输出和错误。任一项失败或停止后不再处理后续项；已完成的外部写入不会回滚，也不自动重试。

每个批处理最多 100 项，可自行调低；最多嵌套 5 层，一次运行共用 2000 个节点的执行预算。禁止递归引用，执行前会校验所有可达子流程与分支，运行使用启动时的流程快照。

导出父流程时一并打包全部引用的子流程（包括草稿节点的引用）；缺少依赖或存在递归引用时拒绝导出。导入会为所有流程生成新 ID 并重连引用，避免覆盖已有流程。包内不含密钥与运行历史；模型和工具凭据仍需在目标工作台配置。被批处理引用的流程须先解除引用才能删除。

## 发布与独立运行

1. 在画布右上角点击“发布”，可选填写版本说明，点击“发布当前草稿”。服务会校验主流程及可达子流程的连线、变量、模型、HTTP 凭据来源和知识库配置；此步骤不调用外部模型或工具。
2. 每次发布新增一个固定版本，保存当时的主流程和全部依赖子流程；继续编辑草稿不会改变旧版本。模型、工具凭据和知识文档按运行时的统一配置读取，停用模型、删除知识库等操作仍会影响旧版运行。
3. 选择历史版本后点击“打开应用”，在独立页面输入内容并运行，可选择真实执行或本地模拟，查看节点日志、最终结果及应用历史。JSON 输入版本会先校验格式；文本版本允许空输入。默认开启对话记忆，也可关闭后独立运行，详见下节。
4. 发布面板的“通过 API 调用”提供可复制的 JavaScript 示例。`POST /api/published/应用ID/run` 接收 `{ "input": "文本或JSON字符串", "version": 1, "mode": "live" }`；省略版本默认最新，省略模式默认真实执行。有效运行请求的 HTTP 200 响应中，`status` 为 `success`、`error` 或 `cancelled`，并返回版本、运行 ID、耗时和日志；调用方应检查 `status`。无效参数、缺失版本、下架和并发超限分别返回 400、404、409、429。
5. “下架应用”阻止新的运行请求，可重新启用；再次发布会自动启用。下架或停止不撤销已发送的外部请求。历史链接明确包含版本号；不带版本的入口默认最新版本。

发布数据以明文流程快照保存在 `.local/published.json`，不包含统一配置中的模型密钥或工具认证值。备份或迁移时还需保留模型、工具和知识库配置；不要把密钥直接写进提示词、URL 或模板。每个应用最多 20 个版本，最多 50 个应用，总文件最多 10 MB；达到上限会拒绝新发布，现有版本保留。当前不提供删除版本。

单次输入最多 10000 字符；服务同时最多运行 3 个已发布请求，总超时 120 秒，超时或连接断开会停止后续执行。日志最多 500 条、总量约 256 KB，单字段最多 4000 字符，超量日志计入 `omittedLogs`。最终输出仍遵循引擎的 100000 字符上限。API 沿用本机来源校验，不提供公网访问、用户鉴权或后台任务恢复；命令行 API 调用的历史由调用方保存。

## 多轮对话

独立应用页默认开启“对话记忆”。第一次发送时创建会话，随后每次提交仍完整执行一次固定版本的工作流；主流程的智能体和大模型节点会在系统提示与当前节点输入之间，携带同一会话最近的用户输入与最终回答。提示词、节点变量和 HTTP 请求保持原有含义，工作台“试运行”仍按单次任务执行。批处理子流程不携带会话上下文，避免不同数组项串扰。

可点击“新会话”从空上下文开始，从“当前会话”选择旧对话继续，或关闭“对话记忆”独立运行（不读写会话）。会话绑定应用、固定版本和运行方式，切换版本或模拟方式时使用各自的列表。本地模拟只保存模板执行结果，不会根据对话生成回答。当前标签页会记住各版本的会话选择，刷新可恢复；其他标签页或重新打开浏览器后，可从列表手动选择。删除会话前需确认，运行历史独立保留；正在运行的会话不能删除或并发发送，返回 HTTP 409。

只有整轮流程成功才写入一对输入和最终输出；后续节点校验失败、运行失败、取消或超时均不进入记忆。已完成的工具写入仍不会回滚。执行成功但会话保存失败时返回成功结果和 `warning`，并标记 `conversationSaved: false`，不要据此自动重复执行有副作用的工具。

API 使用方法：

```js
const root = '/api/published/应用ID';
const { conversation } = await fetch(root + '/conversations', {
  method: 'POST', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ version: 1, mode: 'live' })
}).then(r => r.json());
const result = await fetch(root + '/run', {
  method: 'POST', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ input: '你好', version: 1, mode: 'live', conversationId: conversation.id })
}).then(r => r.json());
// 再次发送时复用 conversation.id，并检查 HTTP 状态和 result.status。
```

`POST /conversations` 省略版本使用当时最新版本，省略模式为 `live`。`GET /conversations?version=1&mode=live` 返回会话摘要，`GET /conversations/会话ID` 返回保留的完整对话，`DELETE /conversations/会话ID` 删除会话。不带 `conversationId` 的原有运行 API 继续独立执行；指定会话时必须使用其绑定版本与模式，错配返回 409，找不到或其他应用的会话返回 404。运行响应增加 `conversationId`、`conversationSaved` 和 `contextTurns`（本轮可用上下文轮数；模拟为 0）。下架阻止创建新会话及运行，但允许查看与删除旧会话。

会话明文保存在 `.local/conversations.json`，包含实际输入与输出，请按本机资料备份和管理；真实执行会将选中会话的近期对话发给统一模型配置指定的服务商。服务重启保留会话，运行中的任务不恢复。最多 100 个会话，总文件 10 MB；每会话保留最近 20 轮、输入输出合计不超过 250000 字符，超量从最早轮次移除并显示数量。单条会话输出最多保留 100000 字符，超长明确标记截断且不进入模型记忆。

模型上下文取最近连续最多 10 轮、总计 60000 字符，按完整消息对移除更早内容；不会拆半轮或跳过大轮次继续使用更旧对话。系统提示、当前输入与上下文合计仍受模型客户端 200000 字符上限约束；这是字符限制，不是 token 限制，模型自身窗口可能更小。尚无摘要压缩、语义长期记忆、流式回复和跨设备会话。

## 运行历史

右上角“运行历史”显示当前工作流的历史。点击节点可展开输入与输出，失败节点默认展开；“将输入用于试运行”仅填入输入，需手动点击运行，不会恢复历史工作流版本。

历史保存在当前浏览器的 `lingjing-runs-v1`，包含实际输入、提示词和输出，不包含模型配置中的 API Key。每个工作流最多 20 次、全局最多 100 次，并受约 1.9 MB 的总存储上限约束；长字段和超量日志会明确标记截断或省略。历史不随工作流 JSON 导出。刷新中断的运行会标记“已中断”，耗时只计至最后保存；不会自动恢复执行。存储不可用时保留内存记录并提示，损坏数据不会被新历史覆盖。

## 快捷键

Ctrl+S 保存；Ctrl+Z 撤销；Ctrl+Shift+Z 重做；Ctrl+D 复制选中节点；Delete 删除节点；Esc 取消连线或选择；? 打开指南。文本编辑时优先使用输入框的原生快捷键。

## 验证

执行 `npm test` 检查流程执行、条件分支、导入校验、连线约束、模型与工具凭据 CRUD、加密存储、HTTP 请求与响应提取、知识文档持久化与检索、接口错误、取消、变量解析、批处理与依赖包、历史持久化、发布版本隔离及运行 API。接口测试使用本机 fake 服务，不消耗真实模型额度。能力范围与后续缺口见 `功能验收.md`。

## 云端开发交接

截至 2026-11-02，已完成十个阶段，最近一阶段为发布应用的多轮对话与本机会话管理。详细实现与验证见 `功能验收.md` 和 `验证记录.md`。当前目标仍是接近 Coze 的核心使用体验，尚不能宣称达到整体能力的 80%。本次按用户要求同步当前完成版本到 GitHub，随后暂停开发，等待新的指示。

- 项目无第三方运行依赖，使用 Node.js 标准库；入口为 `server.cjs`，前端在 `public/`，服务模块在 `lib/`，测试在 `tests/`。
- 模型与工具凭据默认依赖 Windows DPAPI。Linux 云端开发环境可修改源码、运行使用注入存储的测试及查看静态页面；真实模型和凭据管理需先实现安全的跨平台存储，不能直接复制 Windows 的加密文件或改用明文绕过。
- 服务目前仅监听 `127.0.0.1`，带本机来源限制，尚无用户鉴权。上传仓库不等同于部署公网服务；云端部署需要另行处理访问控制、存储和网络配置。
- 仓库不携带 `.local/` 内的配置、知识文档、发布快照和测试运行记录；浏览器中的工作流和历史也不会随代码上传。实际流程请从原工作台导出后迁移，密钥须在目标环境重新配置。
- 待补能力包括自主工具循环、长期记忆、向量语义检索、PDF/Word 解析、while 循环、并行汇聚、完整 JSON Schema、账号协作与云同步。未开始实现自主工具循环，请勿将其作为已交付功能。

继续开发前先核实目标环境和用户优先级，复用现有模块与测试；默认中文沟通，未经用户要求不提交或推送其他改动。
